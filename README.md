# AskSpace · ДЗ3

Учебный сайт вопросов и ответов на Django 5.2 и Bootstrap. Вопросы, ответы, теги, авторы и лайки хранятся в PostgreSQL. Посетители читают публикации, ищут вопросы и переходят по тегам. Для создания и редактирования записей используется админка Django.

## Запуск через Docker Compose

В папке с `manage.py` создайте файлы окружения. Команда использует стандартную библиотеку Python и генерирует ключ Django и пароль базы.

```console
python init_env.py
docker compose up --build -d
```

Откройте [главную страницу](http://localhost:8000/). При первом запуске Django применит миграции и покажет пустой список. Для небольшой демонстрации добавьте данные и создайте свою учётную запись администратора.

```console
docker compose exec web python manage.py fill_db 2
docker compose exec web python manage.py createsuperuser
```

Админка доступна по адресу [/admin/](http://localhost:8000/admin/). Команда `docker compose down` останавливает сервисы. Именованный том `pg_data` сохраняет базу между запусками.

## Локальный запуск

Понадобятся Python 3.12 или 3.13 и PostgreSQL. Для запуска только базы через Compose выполните `docker compose up -d db` после создания файлов окружения. Если используете собственный PostgreSQL, создайте базу и пользователя с правом создания таблиц в этой базе, затем укажите их параметры в `.env.local`.

```console
python init_env.py
python -m venv .venv
```

В Windows PowerShell активируйте окружение командой `.\.venv\Scripts\Activate.ps1`, а в Linux или macOS выполните `source .venv/bin/activate`. Затем запустите:

```console
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Скрипт `init_env.py` выполняется один раз. В `.env.local` хост базы по умолчанию — `127.0.0.1`, в `.env.docker` — имя сервиса `db`. Оба файла исключены из Git и Docker-образа. Перечень переменных приведён в `.env.example`.

## Наполнение базы

`python manage.py fill_db RATIO` добавляет данные одной транзакцией. Повторный запуск создаёт новую партию. В Docker добавьте перед командой `docker compose exec web`.

| Коэффициент | Пользователи и профили | Вопросы | Ответы | Теги | Лайки всего |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 2 | 2 | 20 | 200 | 2 | 400 |
| 10000 | 10000 | 100000 | 1000000 | 10000 | 2000000 |
| 10001 | 10001 | 100010 | 1000100 | 10001 | 2000200 |

Для объёма строго выше порогов ДЗ3 используйте `python manage.py fill_db 10001`. Минимальный коэффициент — 2. Один пользователь может оценить каждую из 110 публикаций только один раз, поэтому при коэффициенте 1 создать 200 уникальных лайков невозможно.

## Проверка сайта

- `/` показывает новые вопросы, `/hot/` сортирует их по числу лайков. Поиск учитывает заголовок, текст и теги.
- Ссылка на тег открывает `/tag/<имя>/`. Заголовок вопроса ведёт на `/question/<id>/`. Списки показывают по 10 вопросов, страница вопроса — по 5 ответов. Несуществующий тег или вопрос возвращает HTTP 404.
- В админке доступны профили, вопросы, ответы, теги и оба вида лайков. Профиль редактируется также на странице пользователя, ответы — на странице вопроса.
- При `DJANGO_DEBUG=1` для локальных запросов подключается Django Debug Toolbar. В панели SQL можно посмотреть запросы для списков и карточек. При `DJANGO_DEBUG=0` приложение панели, middleware и её маршруты отключены.
- Формы из ДЗ2 по-прежнему показывают ошибки заполнения в демонстрационном режиме. Содержание публичных страниц меняется через админку или команду наполнения.
